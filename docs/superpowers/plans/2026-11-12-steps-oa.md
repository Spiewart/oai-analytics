# Knee-Outcomes Module and Steps/Knee-OA Analysis Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
1. Build the shared knee-level module `oai.derive.knee_outcomes` (incidence, progression, measured JSW and replacement, from any anchor visit), and prove it by moving `luyten_early_oa` onto it with identical outputs.
2. Build `analyses/steps_oa` on that module: GT1M steps at 48 and 72 months and incident and progressive knee OA, in both directions.

**Architecture:**
- **Module first (Tasks 1–3).**
  - The module wraps `oai.derive.incident_soa.soa_status` per knee and extends `oai.derive.knee.xray_readings`.
  - It adds readers for `kXR_QJSW_Duryea` and for replacement times.
  - Every function after the readers is a pure function on frames.
- **Then `steps_oa` (Tasks 4–7),** built like `crepitus_activity`:
  - a Python `cohort` step writes frames to OAI_FRAME_DIR;
  - an R `models` step writes aggregate tables.

**Tech Stack:** Python ≥ 3.11 (uv, polars, pytest), R (renv, geepack, survival, `oaimodels`).

**Specs:**
- `docs/superpowers/specs/2026-11-12-knee-outcomes-module-design.md` (Tasks 1–3)
- `docs/superpowers/specs/2026-11-12-steps-oa-design.md` (Tasks 4–7)

## Global Constraints

- **Branch and commits:** branch `claude/oai-step-count-assessment-f42c7b`. Commits carry `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Data stays out of git.** No OAI data in git. Steps come from `OAI_STEPS_DIR` only. Participant-level frames go to OAI_FRAME_DIR. Results are aggregates.
- **No existing analysis's results change.** `luyten_early_oa` outputs are byte-identical before and after Task 3, for the default and every variant. Every existing test still passes.
- **Visits** are two-character codes. **Sides:** `SIDE` ∈ {`R`, `L`} in module outputs. `kXR_QJSW` and `kXR_SQ_BU` code side as `1`/`2`, or `1: Right`, which the module maps.
- **Reading projects:**
  - KL, JSM and JSL come from Project 15 before the anchor (or throughout, when the anchor is V00).
  - At and after an anchor of V06 or later, they come from `readings.followup_project`: `latest` = [43, 37], `p37` = [37]. READPRJ 42 is recoded to 37.
  - The anchor grade follows `readings.anchor_project` (`followup` default, `p15` variant).
  - JSW is Project 16 only.
- **Ledger defaults where a key is absent** (the `incident_soa.setting` pattern):
  - `outcomes.roa_replacement = "ignore"`;
  - `readings.followup_project = "latest"`, `readings.anchor_project = "followup"`;
  - `progression.jsn_rule = "whole_grade"`;
  - `tkr.censor = "last_visit"`;
  - `jsw.threshold_mm = 0.7`, `jsw.middle = "keep"`, `jsw.nonprogressor_mm = 0.5`.
- **steps_oa:**
  - Steps are per 1,000/day. The bands are `lt5000` (the reference), `5000_7499`, `7500_9999` and `ge10000`.
  - Change = later − earlier.
  - `m1` = age, sex, BMI and wear at every device wave the model spans. `m2` adds that knee's 48-month KL and WOMAC pain (forward models; plus the base width for JSW), or `kl_max` and `womac_pain_max` (reverse models).
- **Metric keys:** `<table>.<exposure>.<outcome>.<term>.<model>`, with `.lo`, `.hi`, `.n` and `.events`.
- **No causal wording** ("protect", "harm") in any steps_oa output or results text.

## Review Focus

1. **The unknown middle visit:** ROA at (06, 08, 10) = (F, null, T) → one period, `span` 2, event True. → Task 1 `test_periods_span_unknown_visit`.
2. **Replacement:**
   - under `roa_replacement = "event"`, a replaced knee is an event and leaves the risk set;
   - under `"ignore"` it is censored;
   - a replacement after the last visit day is still an event;
   - a counted replacement with no day is excluded and counted.

   → Tasks 1 and 2.
3. **An unread knee is null, never False,** in `progression`, `by_horizon` and `jsw_change`. → Tasks 1 and 2.
4. **Project preference and readers:**
   - the anchor and the follow-up grades come from the same project under `followup`;
   - Project 15 supplies the anchor under `p15`;
   - READPRJ 42 is read as 37.

   → Task 1 `test_xray_readings_project_preference`, `test_anchor_project`.
5. **Person inclusion in steps_oa:**
   - valid at 48 months only → in P1, P2 and S3b-baseline; out of S1, R1 and R2;
   - steps null with counts valid → only in S4.

   → Task 5 `test_wave_and_steps_inclusion`.

### Task 6: steps_oa models

**Files:**
- Create: `analyses/steps_oa/{models.R,covariates.R,shape.R}`. `covariates.R` is adapted from crepitus_activity, with `level = c("knee", "person")`.
- Test: the R test for `shape.R`, in the repo's R test location.

**Interfaces:**
- **Tables:** `table_{p1,p2,s1,s2,s3,s3b,s4,r1,r2,r3}.csv`, with columns `table, exposure, outcome, term, model, n, events, estimate, lo, hi`.
- **Curves:** `curve_{p1,p2}.csv` (`steps, or, lo, hi`; 2,000–14,000 by 500, relative to 5,000).
- **Metrics:** `metrics_models.csv`.

**Specifications.** Each model uses complete cases on its own terms. A fit error, or a band with fewer than 5 events, writes NA.

- **P1 and P2** (`periods_roa`, `periods_soa`; `incidence.model = "by_horizon"` switches to the horizon frames and drops the period terms):
  - model: `fit_knee_gee(d, "<x> + factor(end_visit) + factor(span) + cov", "event")`;
  - `<x>`: `steps_48` (term `per_1000`); the band factor (terms `band_*`); `rcs_basis(steps_48, knots)` (terms `nonlinear_p` and the curve);
  - P2 also runs within `roa48` True and False (outcomes `soa_roa48`, `soa_noroa48`);
  - in `m2`, `kl48` enters as a factor for SOA and as 0/1 for ROA.
- **S1:** `periods_*_72` with `steps_48` (term `baseline_adj`) + `steps_change` (term `change`), and wear at both waves.
- **S2:** in `tkr.parquet`, restricted to incident-ROA knees. The events come first. If there are at least `tkr.min_events` events: `coxph(Surv(time_yr, event) ~ x + cov + cluster(ID))`. Otherwise, events by band.
- **S3:**
  - Cox replacement in knees with KL ≥ 2 at 48 months;
  - KL and JSN worsening, GEE logistic, among read knees (outcome suffix `_read`).
- **S3b:** in `jsw.parquet`, KL in `progression.risk_kl`:
  - `progressor` (GEE logistic) and `change_mm` (gaussian GEE);
  - each for `steps_48`, and for `steps_48` + `steps_change`;
  - `m2` adds `base_mm`.
- **S4:** P1 and P2 with `mv_min_48` per 10 min/day.
- **R1 and R2:** `steps_72 ~ new_oa_w + steps_48 + cov(48, 72)`, gaussian GEE (independence). The term is `any` or `count`. `r2_kl_read` selects `new_oa_read_48_72`.
- **R3:** the descriptive means repeated with SDs.
- **Every model** runs as `m1` and `m2`.
